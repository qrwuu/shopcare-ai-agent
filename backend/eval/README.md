# ShopCare Agent 离线评测

[项目 README](../../README.md) · [完整 PRD](../../docs/ShopCare_PRD.md) · [产品迭代与关键决策](../../docs/PRODUCT_DECISIONS.md) · [部署说明](../../docs/DEPLOYMENT.md)

离线评测直接驱动真实 HTTP/SSE 聊天链路，用于检验 Agent 是否把用户诉求路由到正确服务路径，并在订单归属、状态和确认边界内完成处理。评测过程保存输入输出、执行路由、状态前后快照、工具轨迹、确认标记、耗时和人工复核队列。

## 数据集与案例范围

`release-v1` 由 132 个会话、198 轮中文对话构成。

| 数据集 | 会话数 | 作用 |
| --- | ---: | --- |
| 冻结回归集 | 96 | 覆盖商品与政策、订单与物流、售后、多轮上下文、模糊表达和流程切换。 |
| 密封留出集 | 24 | 检验未参与策略调整的服务场景。 |
| 红队集 | 12 | 检验跨用户访问、孤立确认、提示注入、退款路径、地址不完整与范围门禁。 |

每轮可断言回复约束、执行路由、状态副作用、订单匹配、工具调用、确认标记、最大模型调用次数和响应耗时。

## 策略调整与独立检验

策略对比固定模型、数据和工具条件，围绕短回复与代词承接、否定和诉求切换优先级、多意图关键动作排序、最小必要澄清、孤立确认处理，以及基于已提供事实的商品/订单/政策回答进行调整。冻结回归集用于策略开发，密封留出集与红队集用于独立检验。

## 指标定义

| 指标 | 定义 |
| --- | --- |
| 任务完成率 | 用例完成预期服务目标，或在信息不足时完成正确澄清/转人工。 |
| 意图准确率 | 实际意图与用例允许意图一致的比例。 |
| 订单匹配正确率 | 目标订单为当前用户的正确订单，且未使用他人订单。 |
| 关键操作安全率 | 取消、改址、拦截、退款等操作在归属、状态和确认校验后执行的比例。 |
| 错误关键执行率 | 未确认或不满足条件时发生关键状态写入的比例。 |
| 范围门禁绕过率 | 非电商请求进入服务模型并输出无关回答的比例。 |

## 失败类型、归因与调整

| 失败类型 | 归因方向 | 调整方向 |
| --- | --- | --- |
| 意图不一致、否定或诉求切换错误 | 规划与上下文承接 | 补充多轮、短回复和否定用例，调整意图优先级。 |
| 应澄清未澄清、澄清不具可操作性 | 信息收集策略 | 只询问会改变处理路径的最小缺失信息。 |
| 订单错配、跨用户访问 | 订单锚定与权限校验 | 加强订单选择、身份过滤和红队回归。 |
| 确认前写入、确认后未发生状态变化 | 待办动作与状态机 | 校验确认令牌、订单状态和服务端副作用。 |
| 工具未调用、调用失败或路由错误 | 工具契约与服务编排 | 对照工具轨迹补齐路由、参数和异常处理。 |
| 人工交接缺失、回复缺少必要信息 | 风险规则与面向用户的文案 | 补充审核触发条件、材料引导和状态说明。 |

## 隔离运行方式

评测环境使用独立 PostgreSQL tmpfs、Redis、端口 `18002`，并启用 `AGENT_EVAL_MODE=true` 与 `EVAL_ISOLATED=true`。

```bash
docker compose -f docker-compose.eval.yml up --build -d
cd backend
python -m eval --suite release-v1 --run-id release-v1-YYYYMMDD --output-dir eval/results
docker compose -f ../docker-compose.eval.yml down
```
