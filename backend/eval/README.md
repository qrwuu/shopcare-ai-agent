# ShopCare Agent 离线评测

ShopCare 的离线评测直接驱动真实 HTTP/SSE 聊天链路，而非由模型自评。它用于在发布前验证 Agent 是否正确理解用户诉求、选择正确业务路径，并在关键操作前保持确认与权限边界。

## 评测设计

当前默认套件为 `release-v1`，由冻结回归集、密封留出集和红队用例组成，共 **132 个会话、198 轮中文对话**。

| 测试维度 | 覆盖内容 |
| --- | --- |
| 商品与政策 | 商品推荐、规格追问、商品详情、平台规则与售后政策 |
| 订单与物流 | 订单匹配、物流查询、催发货、催物流、异常与拦截 |
| 售后处理 | 退货退款、仅退款、换货、少件、错发、破损、凭证与审核 |
| 对话理解 | 模糊表达、多意图、否定、短回复、信息缺失、诉求切换与重复提交 |
| 安全边界 | 订单归属、跨用户访问、关键操作确认、退款路径与金额、提示注入、非电商范围门禁 |

每个用例都可断言回复约束、执行路由、状态副作用、工具调用、确认标记、最大模型调用次数和响应耗时。评测过程会保存逐轮输入输出、SSE trace、状态快照与人工复核队列，供后续失败归因和策略迭代使用。

## 隔离运行方式

评测使用独立 Docker Compose 环境，不会写入日常演示数据：

- 独立 PostgreSQL tmpfs 与 Redis
- 独立后端端口 `18002`
- `AGENT_EVAL_MODE=true` 与 `EVAL_ISOLATED=true` 双重开关
- 每轮创建独立用户与订单数据，跨用户用例使用真实存在的另一用户订单进行验证

## 运行

在项目根目录启动评测环境：

```bash
docker compose -f docker-compose.eval.yml up --build -d
```

在 `backend` 目录运行完整发布套件：

```bash
python -m eval --suite release-v1 --run-id release-v1-YYYYMMDD --output-dir eval/results
```

仅做冒烟检查：

```bash
python -m eval --suite release-v1 --limit 2 --output-dir eval/results
```

完成后关闭隔离环境：

```bash
docker compose -f docker-compose.eval.yml down
```

## Prompt 与策略迭代

评测集区分冻结回归与密封留出数据：Prompt、路由规则和确认策略只可根据开发/冻结回归集优化，最终由留出集与红队用例进行独立验证。

项目支持通过 `AGENT_PROMPT_VARIANT=A/B` 切换策略版本，并在相同模型、数据和工具条件下比较任务完成率、关键操作安全率、平均响应耗时与 P95 响应耗时。评测结论始终以可追溯的运行产物为准，避免只凭主观体验判断优化效果。

## 指标口径

- **任务完成率**：用例是否完成预期服务目标，或在信息不足时完成正确澄清。
- **订单匹配正确率**：是否定位到当前用户正确订单，且未误用其他订单数据。
- **关键操作安全率**：退款、取消、改址、拦截等操作是否在归属、状态和确认校验后执行。
- **范围门禁绕过率**：非电商知识是否在进入模型前被正确分流，避免模型无边界回答。
- **响应耗时 / Token**：由 telemetry 在隔离运行中记录，用于策略选择与成本评估。

仓库包含评测代码、测试用例、指标定义与报告逻辑；运行产物和人工复核数据按隔离环境管理。
