# ShopCare（店小服）项目总览

## 1. 项目定位

ShopCare 是一个面向电商售前、订单服务与售后协同的全栈 AI Agent 项目。项目以消费者端和审核工作台为载体，验证一条可用、可控、可追溯的电商服务链路：用户通过自然语言完成咨询与申请，系统以订单事实、规则校验和状态机保障执行边界，复杂场景由人工审核接续处理。

项目解决的不是单一问答问题，而是电商客服中三类关键体验：

- **理解连续性**：承接商品、订单、规格、售后和短回复上下文，识别否定、切换诉求与多意图表达。
- **业务可靠性**：订单归属、金额、物流、退款和状态变化由后端服务确认，不由模型自由生成。
- **服务闭环性**：从咨询、申请、补材料、审核到通知与结果同步，用户始终能在原对话和售后记录中查看进度。

## 2. 用户角色与服务闭环

| 角色 | 核心目标 | 主要能力 |
| --- | --- | --- |
| 消费者 | 快速解决售前、订单与售后问题 | 商品推荐、政策咨询、订单/物流查询、售后申请、附件上传、进度与通知 |
| 售后审核员 | 在充分上下文下完成风险判断 | 任务队列、用户与订单信息、对话回放、凭证核验、审核说明与历史记录 |

```text
商品与政策咨询
      ↓
订单 / 物流服务
      ↓
售后申请与材料补充
      ↓
自动处理或人工审核
      ↓
结果通知、售后记录与原对话同步
```

通用政策咨询与具体订单操作分层处理：用户可直接询问退换货、运费、发货和退款规则；涉及某笔订单的查询或状态变更时，系统再绑定订单并执行归属、状态和确认校验。

## 3. 产品能力

### 消费者端

- 多轮 AI 客服对话，支持历史会话、订单绑定、商品卡片、订单卡片、图片和凭证附件。
- 商品推荐、规格、颜色、尺码、库存与补货等商品追问；平台规则与售后政策咨询。
- 订单查询、物流查询、催发货、催物流、修改地址、取消订单与物流拦截申请。
- 退货退款、仅退款、换货、少件、错发、破损等售后场景，支持补充材料和状态跟踪。
- 售后进度、审核结果、补材料提醒和消息未读状态在页面刷新与重新登录后恢复。

### 审核工作台

- 队列按风险等级、等待时间和当前阶段展示待办与历史任务。
- 单个审核任务聚合用户信息、订单/商品、售后金额与状态、完整会话、用户附件、规则核验、触发原因和操作日志。
- 支持同意、拒绝、要求补充材料和填写审核说明；补材料后任务回到队列，所有历史记录持续保留。

## 4. Agent 与业务执行设计

ShopCare 采用“**LLM 负责理解与表达，业务服务负责事实与执行**”的架构。

| 分层 | 作用 | 是否可写业务数据 |
| --- | --- | --- |
| 范围与风险门禁 | 识别非电商问题、隐私风险、异常资金诉求 | 否 |
| 对话理解与上下文 | 识别意图、多意图、短回复、澄清信息与诉求切换 | 否 |
| 政策与目录服务 | 提供商品、规格、库存和规则事实 | 否 |
| 可信业务执行器 | 查询订单、创建或撤销售后、改址、取消、拦截、建审核任务 | 是 |
| 人工审核 | 处理高风险、证据冲突与用户主动转人工 | 是 |

关键操作均遵循统一的“**说明影响 → 收到确认 → 规则校验 → 执行与同步**”机制。执行器会重新校验当前用户、订单归属、订单状态、售后状态和金额，确保模型不能通过文本绕过业务规则。

LangChain 用于模型调用和结构化输出，LangGraph 提供兼容工作流与检查点能力；会话层持久化当前订单、待确认动作、规格选择、地址草稿、售后状态和附件元数据，使短回复能够在正确业务上下文中被理解。

## 5. 数据与状态一致性

售后申请作为统一业务记录，驱动以下界面和事件：

- `/chat` 的售后进度卡与原对话消息
- `/after-sales` 的售后记录、时间线与操作入口
- `/admin` 的审核队列、审核详情与历史记录
- 消费者未读通知和已读状态

状态更新优先通过 WebSocket 推送，客户端以轮询恢复作为保障；退款完成、撤销售后、补材料、审核结果等动作都会同步更新关联订单、消息、任务和通知，避免页面各自维护不一致的本地状态。

## 6. 技术架构

```text
Next.js 15 / React 19 消费者端与审核端
                  │ REST · SSE · WebSocket · JWT
                  ▼
            FastAPI API 与业务服务
  ┌───────────────┼────────────────┐
  │               │                │
Agent 编排     售后状态机        审核 / 附件 / 通知
  │               │                │
  └──── LangChain / LangGraph ────┘
                  │
 PostgreSQL + pgvector · Redis · Celery · OpenAI 兼容模型网关
```

- **前端**：Next.js 15、React 19、TypeScript、Tailwind CSS
- **后端**：FastAPI、SQLModel、Alembic、JWT、SSE、WebSocket
- **Agent**：LangChain、LangGraph、结构化计划、政策与目录检索
- **基础设施**：PostgreSQL + pgvector、Redis Stack、Celery、Docker Compose

## 7. 离线评测与迭代

项目提供独立 Docker 评测环境，真实调用 HTTP/SSE 对话链路，并对每轮对话记录执行路由、状态前后快照、工具轨迹、确认标记、耗时与人工复核信息。

`release-v1` 发布套件覆盖商品咨询、政策解释、订单匹配、物流、售后、补证、流程切换、关键操作确认、跨用户访问、提示注入与范围门禁。

| 指标 | 当前发布结果 |
| --- | --- |
| 任务完成率 | **98.48%（130 / 132）** |
| 意图识别正确率 | **100%** |
| 订单匹配正确率 | **100%** |
| 关键操作安全率 | **100%** |
| 错误关键执行率 | **0%** |
| 非电商范围门禁绕过率 | **0%** |

评测体系同时支持 Prompt A/B、规则策略调整、冻结回归、密封留出集和红队用例，确保优化建立在可复现的质量对比上。详细运行方式见 [Agent 离线评测说明](../backend/eval/README.md)。
